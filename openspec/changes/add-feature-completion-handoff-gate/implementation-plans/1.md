# Task 1 Implementation Plan

## Objective

Make the feature-completion handoff in `complete-task` explicit so task completion can deterministically report whether the feature stays in `[IN_PROGRESS]` or is ready to move to `[DONE]`.

## Context

- Change: `openspec/changes/add-feature-completion-handoff-gate/`
- Task: `1` `Feature Completion Handoff`
- Related specs:
  - `openspec/changes/add-feature-completion-handoff-gate/specs/task-execution-handoff/spec.md`
  - `openspec/changes/add-feature-completion-handoff-gate/specs/feature-execution-tracking/spec.md`

## Scope

- Add workflow helper logic that can evaluate the completion-time handoff from the active task into either:
  - feature remains in `[IN_PROGRESS]`, or
  - feature is eligible to move to `[DONE]`
- Expose that handoff result through `skills/complete-task/scripts/resolve_complete_task.py`
- Add narrow automated coverage for the new resolver/helper behavior

## Expected Files

- `skills/_workflow/workflow_state.py`
- `skills/complete-task/scripts/resolve_complete_task.py`
- `tests/test_workflow_openspec_integration.py`
- `skills/_workflow/tests/test_workflow_state.py`

## Test Strategy

1. Add a failing test for the completion resolver/helper behavior first.
2. Run the narrow unittest target that covers the new failure.
3. Implement the minimal helper and resolver output changes.
4. Re-run the narrow test targets until green.
