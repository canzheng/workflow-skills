# Task 2 Implementation Plan

## Objective

Make `finish-feature` the owner of the terminal feature transition so it starts from `[IN_PROGRESS]`, requires all top-level OpenSpec tasks done plus `Current Task: none`, and only moves a feature to `[DONE]` after acceptance plus OpenSpec validation/archive succeed.

## Context

- Change: `openspec/changes/add-feature-completion-handoff-gate/`
- Task: `2` `Finish-Feature Alignment`
- Related specs:
  - `openspec/changes/add-feature-completion-handoff-gate/specs/task-execution-handoff/spec.md`
  - `openspec/changes/add-feature-completion-handoff-gate/specs/feature-execution-tracking/spec.md`

## Scope

- Make `finish-feature` resolve eligible features from `[IN_PROGRESS]` instead of `[DONE]`
- Require the finish-feature resolver to reject features whose top-level OpenSpec tasks are not all done or whose `Current Task` is not `none`
- Keep `complete-task` on task closure and handoff only, without owning the `[IN_PROGRESS] -> [DONE]` transition
- Update workflow audit and workflow skill docs so `[DONE]` remains a post-acceptance, post-archive state
- Add narrow regression coverage for both startability and rejection paths at the new final-task boundary

## Test Strategy

1. Add failing regression tests for the new finish-feature startability and rejection rules first.
2. Run the narrow unittest targets and confirm the new failures are real.
3. Make the minimal resolver, helper, audit, and doc changes.
4. Re-run the narrow unittest targets until green.
