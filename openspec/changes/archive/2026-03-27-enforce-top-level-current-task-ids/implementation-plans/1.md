## Plan

### 1. Establish a failing test first

- Add a narrow unit test proving a nested-style `Current Task` value such as `1.1` is rejected as invalid workflow metadata.
- Run the smallest relevant test target and confirm the new test fails for the expected reason before changing production code.

### 2. Add shared validation for `Current Task`

- Update the shared feature-metadata parser/helper to accept only `none` or a top-level numeric task id.
- Keep the returned value shape unchanged for valid inputs so downstream task resolution continues to behave the same way.

### 3. Re-run the narrow checks

- Re-run the targeted workflow-state test target and confirm the new validation is green.
- Re-run `python "${CODEX_HOME:-$HOME/.codex}/skills/audit-workflow/scripts/audit_workflow.py"` in the feature worktree after the workflow-state update from `start-task`.
