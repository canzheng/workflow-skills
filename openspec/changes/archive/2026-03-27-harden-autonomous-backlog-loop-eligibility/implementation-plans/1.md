# Task 1 Implementation Plan

## Objective

Make autonomous task selection stop when active `[READY]` or `[IN_PROGRESS]` work lacks valid active OpenSpec linkage or carries workflow-derived readiness drift, instead of returning `run_task_loop` for malformed state.

## Context

- Change: `openspec/changes/harden-autonomous-backlog-loop-eligibility/`
- Task: `1` `Eligibility validation`
- Linked context:
  - `openspec/changes/harden-autonomous-backlog-loop-eligibility/proposal.md`
  - `openspec/changes/harden-autonomous-backlog-loop-eligibility/design.md`
  - `openspec/changes/harden-autonomous-backlog-loop-eligibility/tasks.md`
  - `openspec/changes/harden-autonomous-backlog-loop-eligibility/specs/task-execution-handoff/spec.md`
  - `openspec/changes/harden-autonomous-backlog-loop-eligibility/specs/workflow-audit-and-repair/spec.md`

## Scope

- Keep this task limited to autonomous resolver validation for active `[READY]` and `[IN_PROGRESS]` features.
- Reject malformed active work when it is missing `OpenSpec Change` metadata, links to a missing active change directory, or carries workflow-derived task-readiness drift.
- Preserve the existing autonomous action precedence once active work has passed those checks.
- Do not refactor the resolver to reuse additional shared helpers in this task; task `2` owns that policy-alignment work.
- Do not add the broader malformed/repaired fixture matrix in this task; task `3` owns the heavier coverage expansion.

## Expected Files

- Modify: `skills/autonomous-backlog-loop/scripts/resolve_autonomous_backlog_action.py`
- Modify: `skills/_workflow/tests/test_workflow_scripts.py`

## Plan

### 1. Establish failing script-level tests first

- Add narrow autonomous-resolver tests covering malformed active features with missing OpenSpec linkage.
- Cover both the directly selected malformed active feature case and the "do not route around malformed active work" case.
- Run only the new targeted tests first and confirm they fail for the expected linkage-validation reason before changing production code.

### 2. Add active-feature linkage validation in the resolver

- Validate active `[READY]` and `[IN_PROGRESS]` features before returning `run_task_loop`.
- Keep the error explicit and feature-scoped so the malformed state is actionable.
- Preserve the current shaping/backlog fallback behavior once active work is valid.

### 3. Re-run narrow checks

- Re-run the targeted autonomous resolver tests after the code change.
- Re-run `python "${CODEX_HOME:-$HOME/.codex}/skills/audit-workflow/scripts/audit_workflow.py"` in the feature worktree with task `1` active.
