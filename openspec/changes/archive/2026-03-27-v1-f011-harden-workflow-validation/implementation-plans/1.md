## Objective

Make `diagnose-workflow` report missing planning scaffold as structured findings instead of raising when `docs/planning/current_version` or the active `BACKLOG.md` is missing.

- Change: `openspec/changes/v1-f011-harden-workflow-validation/`

  - `openspec/changes/v1-f011-harden-workflow-validation/specs/openspec-change-integration/spec.md`

## Scope

- Keep the task limited to diagnosis control flow when the planning scaffold is malformed.
- Prevent diagnosis from calling linkage collection when the active planning scaffold is missing.
- Preserve diagnosis as a read-only JSON report with structured findings and `issues_found` status.
- Do not add shaping-artifact enforcement in this task; task `2` owns that broader validation change.
- Do not change audit behavior or stable specs in this task.

## Expected Files

- Modify: `skills/diagnose-workflow/scripts/diagnose_workflow.py`
- Modify: `tests/test_diagnose_workflow.py`

## Plan

### 1. Establish failing diagnosis tests first

- Add narrow tests covering a missing `docs/planning/current_version` symlink and a missing active `BACKLOG.md`.
- Verify each new test fails because the script currently raises instead of returning structured findings.

### 2. Guard linkage collection behind scaffold availability

- Keep the existing structured finding emission for missing scaffold state.
- Skip `collect_openspec_change_linkage(...)` unless the planning scaffold is present enough for that helper to run safely.
- Preserve the current orphan-active-change behavior when the scaffold is valid.

### 3. Re-run narrow verification

- Re-run `bin/run-python.sh -m pytest tests/test_diagnose_workflow.py -q`.
- Re-run `bin/run-python.sh skills/audit-workflow/scripts/audit_workflow.py` with task `1` active in the feature worktree.

- This repo already runs `pytest` through `bin/run-python.sh`; use that wrapper for narrow task verification.
