## Scope

- Keep the missing-target-file path as a hard installer failure.
- Add an initialization path for an existing target `AGENTS.md` that lacks the managed workflow markers.
- Ensure the initialization path appends exactly one managed workflow section and does not change the replace-in-place flow for already-managed files.
- Document the installer's `rsync` dependency in contributor-facing docs covered by this task.
- Keep environment constraints and any extra regression-only work out of this task; those belong to tasks `2` and `3`.

## Expected Files

- Modify: `install.sh`

## Plan

### 1. Add failing installer tests first

- Extend `tests/test_install_script.py` with a case showing that an existing `AGENTS.md` without markers should install successfully and gain exactly one managed workflow section.
- Keep the existing missing-target-file failure coverage intact and re-run the focused installer test module to confirm the new expectation fails for the right reason before changing production code.

### 2. Update installer control flow minimally

- Preserve the current hard failure when `${CODEX_HOME:-$HOME/.codex}/AGENTS.md` is missing.
- Detect the "file exists but markers are absent" case and append the managed workflow block from `AGENTS-global-workflow.md` directly, while leaving the existing replace-in-place path for marker-managed files unchanged.
- Avoid introducing duplicate managed blocks or relaxing the source-file marker validation.

### 3. Document the installer dependency and rerun narrow verification

- Update `README.md` installation notes to state that `install.sh` requires `rsync`.
- Re-run `bin/run-python.sh -m unittest tests.test_install_script -v`.
- Re-run `python "${CODEX_HOME:-$HOME/.codex}/skills/audit-workflow/scripts/audit_workflow.py"` with task `1` active in the feature worktree.
