## Contract Surface

- Change Type: `behavioral`
- Workflow Surfaces:
  - `start-task` entry gate for executable OpenSpec tasks
  - `complete-task` pre-closure gate for active tasks
  - shared implementation-plan parsing used by both resolvers
- Surrogate Drift Risks:
  - helper-only plan content silently treated as sufficient
  - stale test fixtures normalizing weaker contracts than execution requires

## Proof Obligations

- `start-task` refuses execution when the linked implementation plan is missing required proof-coverage sections or leaves them empty.
- `complete-task` reuses the same implementation-plan validation and refuses closure when the active plan does not satisfy the stronger structure.
- The stronger plan contract is reflected in resolver and integration fixtures so tests no longer encode the weaker “any plan file exists” behavior.

## Plan

### 1. Add shared implementation-plan validation helpers

- Define a compact Markdown structure with required sections for contract surface, proof obligations, and validation plan.
- Add shared parsing and validation helpers in `skills/_workflow/workflow_state.py` so both resolvers use the same rules.
- Keep the rules strict enough to reject empty placeholder content without introducing a complex Markdown schema.

### 2. Apply the shared gate in execution resolvers

- Update `resolve_start_task.py` to validate the selected task's implementation plan before returning a startable payload.
- Update `resolve_complete_task.py` to validate the active task's implementation plan before returning a completable payload.
- Preserve the existing missing-file errors, but add new structural-plan errors when the file exists and is still too weak.

### 3. Update tests and fixture plans

- Replace the minimal implementation-plan fixture text in integration tests with the stronger required structure.
- Update or add resolver tests that prove structurally invalid plans are rejected.
- Fix the stale cross-feature `start-task` expectations by creating compliant downstream plans in those fixtures.

## Notes

- This task intentionally enforces explicit proof structure, not full semantic equivalence with design prose. The workflow prose and reference alignment follow in task `2`.
