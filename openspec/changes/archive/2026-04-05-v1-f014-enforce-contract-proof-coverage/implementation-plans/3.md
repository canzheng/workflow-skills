## Contract Surface

- Change Type: `behavioral`
- Workflow Surfaces:
  - task completion resolution
  - feature validation-log evidence
  - the canonical feature-file template
  - the workflow reference used by planning-state workflows
- Surrogate Drift Risks:
  - `complete-task` accepting helper-only or unrelated proof because the feature file stores only generic success text
  - validation evidence that mentions a successful command but not the obligation or evidence category it satisfied
  - feature guidance that does not show authors how to record categorized evidence in the active workflow record

## Proof Obligations

- `complete-task` rejects task closure unless the active task's validation log contains categorized evidence that matches the task's declared proof obligations.
- Evidence entries are written in the shared taxonomy so the resolver can inspect them deterministically.
- The active task's proof-obligation surface is translated into one or more expected evidence categories, so helper-only or unrelated evidence cannot satisfy closure for a behavioral task.
- The resolver continues to produce the existing completion handoff metadata when evidence is sufficient.
- The feature template and workflow reference show how to record categorized evidence for the active task.

## Plan

### 1. Add evidence parsing helpers

- Extend `skills/_workflow/workflow_state.py` with helpers that locate the active task's validation-log block and extract evidence text from that block.
- Normalize the evidence text into shared categories so the completion gate can compare task evidence against the proof-obligation surface.

### 2. Enforce obligation-aware completion

- Update `skills/complete-task/scripts/resolve_complete_task.py` to require categorized evidence before allowing task closure.
- Derive the expected evidence categories from the task plan's contract surface and proof-obligation text before comparing them to the feature validation log.
- Keep the existing completion handoff contract intact when evidence is sufficient.
- Reject validation-log entries that only report success generically or only name unrelated helper proof.

### 3. Align the documentation surface

- Update the feature template and workflow reference so validation-log guidance shows categorized evidence in the active workflow record.
- Update the active feature file handoff note so task `3` is recorded as in progress with the evidence-reconciliation scope.

### 4. Add focused regression tests

- Add unit coverage for the evidence parsing and category normalization helpers.
- Add integration coverage for accepted obligation-aligned evidence and rejected narrow proof in the completion resolver.
