## Task 2 Plan: Runtime Remediation

### Context

Task 2 fixes the two remaining runtime inconsistencies from the reopened `v1-f018` review:

- selected-feature continuation still falls back to the current checkout when the intended active feature worktree is missing
- structured review verdicts can be parsed, but no workflow resolver currently consumes emitted verdict state in a runtime path

Task 2 should keep the change surface narrow. The continuation payload shape is already accepted, and task 1 already aligned the operator-facing workflow guidance.

### Scope

- Update `skills/_workflow/workflow_state.py` so selected-feature repo-root resolution fails closed when an active `[IN_PROGRESS]` feature cannot be resolved to a unique non-primary feature worktree.
- Update `skills/start-task/scripts/resolve_start_task.py` to expose the latest readiness review verdict for the selected feature when canonical readiness verdict lines are present, so downstream runtime workflow can consume structured review state instead of prose-only notes.
- Ensure `skills/autonomous-backlog-loop/scripts/resolve_autonomous_backlog_action.py` inherits the stricter selected-feature worktree resolution through the shared helper.
- Add or update tests in `tests/test_workflow_openspec_integration.py` and `skills/_workflow/tests/test_workflow_state.py` to cover the missing-worktree failure path and readiness-verdict consumption.

### Implementation Steps

1. Add failing tests for the missing-worktree selected-feature continuation path and the readiness review-verdict runtime consumer path.

3. Add a small helper for selecting the latest structured review verdict for a given scope/target and use it in `resolve_start_task.py` to surface readiness verdict state in the resolver payload.
4. Re-run the narrow runtime test slice and the workflow audit until the runtime behavior matches the reopened remediation design.
