## Implementation Notes

- The `run_resolver` helper caches one `importlib` module load per resolver script path, captures stdout/stderr via `contextlib.redirect_stdout`/`redirect_stderr`, catches `SystemExit` to translate argparse's exit-2 path, and returns a simple `ResolverResult` namedtuple with `.returncode`, `.stdout`, `.stderr`.
- Conversion pattern per test: replace `result = subprocess.run(["python3", str(SCRIPT), "--repo-root", str(repo)], capture_output=True, text=True, check=False)` with `result = run_resolver(SCRIPT, ["--repo-root", str(repo)])`. All existing `.returncode`, `.stdout`, `.stderr` assertions continue to pass.
- The scripts' bootstrap (`for _candidate in Path(__file__).resolve().parents: if (_candidate / "_workflow").is_dir(): sys.path.insert(0, str(_candidate)); break`) works identically under importlib because `__file__` resolves to the real script path; importlib does not alter that resolution.
- The `_git(...)` helper in the integration test file uses `subprocess.run(["git", ...])` to drive a real `git` binary — it is out of scope; git is an external tool, not a Python resolver. Those calls stay subprocess.
- Subprocess smoke set: retain three tests that preserve the full end-to-end CLI path — one for `start-task`, one for `complete-task`, and one for `audit-workflow` — so the installed-script fork path is still exercised at least once per major resolver family. The rest convert.
- Shared factories (`write_backlog(...)`, `write_feature_file(...)`, `write_openspec_change(...)`, `initialize_repo_scaffold(...)`) encapsulate the scaffolds currently inlined via textwrap.dedent across the integration tests and `tests/test_diagnose_workflow.py`. Migration of existing tests to consume these factories is additive; tests that would grow in churn without clear benefit may keep their inline scaffolds if the conversion would inflate the diff.
