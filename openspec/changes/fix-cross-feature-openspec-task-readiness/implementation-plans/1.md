# Shared Dependency Resolution Implementation Plan

> **Task:** `1` from `fix-cross-feature-openspec-task-readiness`
> **Execution mode:** Use `subagent-driven-development` or inline execution in the feature worktree.

**Goal:** Make OpenSpec-backed task status derivation resolve cross-feature dependencies through the shared dependency model, including archived upstream changes for completed features.

**Scope:** Limit this task to shared helper logic and narrow regression coverage. Do not update `start-task`, autonomous resolver callers, or broader fixture suites in this task.

## Files

- Modify: `skills/_workflow/workflow_state.py`
- Modify: `skills/_workflow/tests/test_workflow_state.py`
- Optional if helper coverage needs integration proof: `tests/test_workflow_openspec_integration.py`

## Plan

### 1. Add failing coverage for archived upstream dependencies

- Write a test in `skills/_workflow/tests/test_workflow_state.py` that models:
  - a downstream OpenSpec-backed feature with a dependency like `v1-f001/1`
  - an upstream completed feature whose linked change exists only under `openspec/changes/archive/`
  - an unchecked downstream task that should become `ready`
- Run the narrow test target and confirm it fails for the expected reason before changing implementation.

### 2. Unify OpenSpec task status derivation with shared dependency resolution

- Refactor `skills/_workflow/workflow_state.py` so OpenSpec-backed task status derivation stops hard-coding feature-qualified dependencies as unsatisfied.
- Reuse the same dependency-resolution model already used by readiness drift so task parsing, readiness drift, and later caller alignment can share one status interpretation.
- Keep legacy inline task parsing unchanged.

### 3. Extend linked change lookup for archived upstream features

- Update the shared workflow-state helper path that loads another feature's tasks so it can resolve:
  - active linked changes under `openspec/changes/<change-id>/`
  - archived linked changes under `openspec/changes/archive/*-<change-id>/`
- Preserve current behavior for missing or ambiguous feature/change references by continuing to surface unknown dependency errors.

### 4. Verify narrow workflow coverage

- Run:
  - `pytest skills/_workflow/tests/test_workflow_state.py -q`
- If task-1 coverage requires it, also run one targeted integration test selection from `tests/test_workflow_openspec_integration.py`.
- Only broaden verification if the narrow suite exposes cross-file regressions.
