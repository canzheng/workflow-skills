# Task 1 Implementation Plan

## Objective

Tighten the shared workflow validation layer so it can detect malformed canonical backlog section layouts and promoted feature files that omit linked `OpenSpec Specs` metadata, without yet changing the `audit-workflow` or `diagnose-workflow` command surfaces that consume those checks.

## Context

- Change: `openspec/changes/v1-f010-close-workflow-review-gaps/`
- Task: `1` `Tighten shared workflow structural validation`
- Linked context:
  - `openspec/changes/v1-f010-close-workflow-review-gaps/proposal.md`
  - `openspec/changes/v1-f010-close-workflow-review-gaps/design.md`
  - `openspec/changes/v1-f010-close-workflow-review-gaps/tasks.md`
  - `openspec/changes/v1-f010-close-workflow-review-gaps/specs/workflow-audit-and-repair/spec.md`

## Scope

- Keep this task limited to shared validation and parsing helpers under `skills/_workflow/`.
- Add helper-level detection for:
  - missing, out-of-order, or extra canonical workflow board sections
  - promoted OpenSpec-backed feature files with missing `OpenSpec Specs` entries
- Preserve existing task-readiness and feature-resolution behavior outside those new helper seams.
- Do not fully wire the new checks into `audit-workflow` or `diagnose-workflow` in this task; task `2` owns those command-level integrations.
- Do not add the broader regression matrix for audit/diagnose fixtures in this task; task `3` owns that coverage.

## Expected Files

- Modify: `skills/_workflow/workflow_state.py`
- Modify: `skills/_workflow/tests/test_workflow_state.py`
- Optional only if helper seams require a tiny adjacent import or compatibility adjustment: `skills/_workflow/__init__*`

## Plan

### 1. Add failing helper-level tests first

- Extend `skills/_workflow/tests/test_workflow_state.py` with narrow cases for:
  - a backlog containing an extra canonical-like section after `[DEFER]`
  - a backlog with canonical sections out of order
  - a promoted feature file that has an `OpenSpec Change` but no linked `OpenSpec Specs`
- Keep the assertions focused on shared helper outputs rather than current audit/diagnose CLI wording.

### 2. Introduce shared structural validation helpers

- Add a helper that inspects backlog headings and reports whether the workflow sections are exactly the canonical set in order, including rejection of extras after `[DEFER]`.
- Add a helper that inspects feature metadata and returns the linked stable `OpenSpec Specs` paths, plus a validation seam that distinguishes promoted OpenSpec-backed features from `legacy-exempt` completed features.
- Keep the helper outputs structured so later audit and diagnose integration can reuse them without reimplementing the rules.

### 3. Verify the shared layer narrowly

- Run the narrow workflow-state test target first:
  - `bin/run-python.sh -m pytest skills/_workflow/tests/test_workflow_state.py -q`
- Re-run workflow audit after the task-start bookkeeping changes settle in the worktree:
  - `bin/run-python.sh skills/audit-workflow/scripts/audit_workflow.py`

## Notes

- Task `2` should consume the new helper seams instead of duplicating section-shape or feature-metadata validation inside individual scripts.
- If the helper API needs to expose both machine-readable details and stable human-readable messages, keep message formatting centralized in the shared layer where practical.
