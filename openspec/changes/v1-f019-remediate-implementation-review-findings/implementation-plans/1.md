## Task 1 Plan: Shared CLI Helpers And Script Deduplication

### Context

Task 1 is the structural refactor pass for `v1-f019`. Review findings 1, 4, and 10 identified three sources of drift across the nine skill entry scripts: each script redefines `WorkflowError`, `repo_root()`, and (in four cases) `read_backlog()`; `_list_git_worktree_roots` diverges from its public twin on the failure contract; `SKILLS_ROOT = Path(__file__).resolve().parents[2]` breaks silently on any relocation; and `audit_workflow.py` redefines regex constants already exported from `_workflow.workflow_state`. The shaped design (see `design.md` → "Decision: Extract a single `cli_helpers` module") captures the exact migration shape.

This task is behavior-preserving. No script gains or loses a CLI flag during Task 1. Contract changes (e.g., the ambiguity-driven `--feature-id` contract from Task 2) happen in later tasks so refactor and contract change land in separate reviews.

### Scope

- Create `skills/_workflow/cli_helpers.py` exporting `WorkflowError`, `repo_root()`, `load_backlog()`, and an anchor-based `resolve_skills_root()`.
- Migrate all nine skill entry scripts (`audit-workflow`, `diagnose-workflow`, `shape-backlog-item`, `start-task`, `complete-task`, `finish-feature`, `prioritize-backlog`, `autonomous-backlog-loop`, `initialize-workflow-artifacts`) to import `WorkflowError`, `repo_root`, and (where applicable) `load_backlog` from the shared module. Remove the per-script copies.
- Delete the private `_list_git_worktree_roots` in `skills/start-task/scripts/resolve_start_task.py` and converge callers on the public helper in `skills/_workflow/workflow_state.py`. Failure contract: `[root.resolve()]` on git error, matching the public helper at `workflow_state.py:254`.
- Drop the redundant `FEATURE_ID_RE` and `TASK_STATUS_RE` redefinitions at `skills/audit-workflow/scripts/audit_workflow.py:30-32` and import them from `_workflow.workflow_state`. Leave `BACKLOG_REF_RE` in place since it is unique to `audit-workflow`.
- Replace every `SKILLS_ROOT = Path(__file__).resolve().parents[2]` with the new anchor-based `resolve_skills_root()` that walks upward from `__file__` looking for a `_workflow/` sibling marker directory.

### Pre-decided `load_backlog` contract

The four existing `read_backlog` implementations have divergent signatures (checked during plan authoring): `start-task` / `complete-task` return `(backlog_path, parsed_backlog)`; `autonomous-backlog-loop` returns `(backlog_path, feature_sections_dict, active_task_payloads)` by doing extra per-section feature-file loading; `prioritize-backlog` returns `(backlog_path, backlog_text, parsed_backlog)` and also uses a separate `resolve_backlog` helper.

To avoid a confused superset, `cli_helpers.load_backlog(root)` returns the minimal common tuple:

```
(backlog_path: Path, backlog_text: str, parsed_backlog: ParsedBacklogDocument)
```

- `start-task` and `complete-task` call `load_backlog(root)` and discard `backlog_text`.
- `prioritize-backlog` calls `load_backlog(root)` and uses all three values; the existing `resolve_backlog` helper in `workflow_state.py` is no longer the canonical entry point for these callers.
- `autonomous-backlog-loop`'s per-section feature-file loading and `FeatureRecord` construction stays in the script (not moved into the shared helper), since that behavior is loop-specific. The script calls `load_backlog(root)` to get the common core and then does its own per-section work.

This is the behavior-preserving shape. No caller loses access to a value it currently consumes.

### Implementation Steps

1. Read the four existing `read_backlog` implementations (`start-task`, `complete-task`, `autonomous-backlog-loop`, `prioritize-backlog`) side by side. Determine whether their return types and side effects already agree or whether the shared helper must expose the superset.
2. Read the existing `repo_root` implementations across the nine scripts. Confirm they are byte-identical (verified by grep during review) and lift one copy into `cli_helpers.py`.
3. Implement `resolve_skills_root()` by walking upward from `__file__` for the `_workflow/` sibling marker. Add a direct test under `skills/_workflow/tests/` that exercises the walk-up from a relocated script path.
4. Implement `cli_helpers.py` with the four exports. Keep behavior byte-identical to the current per-script copies.
5. Migrate each of the nine entry scripts:
   - replace the local `class WorkflowError(RuntimeError)` with `from _workflow.cli_helpers import WorkflowError`
   - replace the local `def repo_root` with `from _workflow.cli_helpers import repo_root`
   - replace the local `def read_backlog` (four scripts) with `from _workflow.cli_helpers import read_backlog`
   - replace `SKILLS_ROOT = Path(__file__).resolve().parents[2]` with the `resolve_skills_root()` call
6. In `skills/start-task/scripts/resolve_start_task.py`, delete the private `_list_git_worktree_roots`. Route callers to `_workflow.workflow_state.list_git_worktree_roots`. Converge on the public helper's failure contract (`[root.resolve()]` on git error, per `workflow_state.py:254`). Update the resolver's negative-path handling so the fail-closed behavior described in the L-002 lesson is preserved.
7. In `skills/audit-workflow/scripts/audit_workflow.py`, remove the local `FEATURE_ID_RE` and `TASK_STATUS_RE`. Import both from `_workflow.workflow_state`. Confirm the `BACKLOG_REF_RE` pattern stays local.
8. Run the full test suite and confirm behavior parity: `bin/run-python.sh -m unittest discover -s tests` and `bin/run-python.sh -m pytest skills/_workflow/tests -q`.
9. Run `audit-workflow` from the feature worktree and confirm the workflow state is still valid.
